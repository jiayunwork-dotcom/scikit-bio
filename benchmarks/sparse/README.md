# Sparse phylogenetic-diversity resource benchmark

Reproducible record of the memory and time behavior of the sparse
Faith's PD / UniFrac pipeline on a wide, sparse count table. Everything runs
in independent processes and never materializes a dense sample-by-taxon or
sample-by-node matrix.

## Fixture

* Tree: an approximately balanced binary tree with **200,000 distinct tip
  names** (`tip0000000` ... `tip0199999`). Every non-root branch has length
  1.0; the root edge is unset. Built level by level from `TreeNode` objects
  (`bench_sparse.py::build_balanced_tree`), not from a Newick string or a
  dense adjacency matrix.
* Counts: **256 samples**, each with **32 non-negative integer counts**,
  generated directly in CSR form with a fixed seed (`--seed 20261119`).
  Stored values are integers in `[1, 100)`; repeated coordinates within a row
  are merged, so every row has at most 32 logical non-zero columns.
* Two overlap regimes:
  * *dispersed*: leaves sampled from all 200,000 tips;
  * *clustered*: every sample draws from one small clade (tips `0..4095`),
    forcing heavy sharing of ancestor rows.
* Inputs exercised: `scipy.sparse.csr_matrix`, `scipy.sparse.csr_array`, and a
  BIOM `skbio.table.Table` (which stores observations x samples as CSC).

For scale, the dense sample-by-taxon `float64` equivalent of this table would
be `256 * 200000 * 8 = 409,600,000 bytes` (~0.381 GiB); the sparse CSR
representation of the same logical table is ~97 KiB.

## Protocol

Each metric/input combination runs in its **own process**:

```bash
python -I bench_sparse.py --metric {faith_pd|unweighted_unifrac|weighted_unifrac} \
    --input {csr|csr_array|biom} [--normalized] [--clustered] [--seed N]
```

1. Imports and one warm-up metric call complete first (the warm-up settles
   SciPy/NumPy allocator caches).
2. The tree, CSR table, taxa and sample labels are constructed; RSS is read
   after a forced `gc.collect()` and recorded as the baseline.
3. A **single** metric call is timed with `time.perf_counter()`.
4. Peak RSS comes from `resource.getrusage(RUSAGE_SELF).ru_maxrss` (Linux:
   kilobytes), which accounts for every allocation in the process, including
   NumPy/SciPy native buffers -- not just Python-tracked objects.
5. Reported memory growth is `ru_maxrss(after) - RSS(baseline)`, so fixture
   construction is excluded from the call budget.

Run the full matrix with:

```bash
bash run_all.sh results/
```

## Recorded results (Python 3.11, Linux aarch64, seed 20261119)

All 18 runs stay far below the 256 MiB peak-growth budget (worst observed
growth: ~13 MiB). Numbers are from `results/*.json`, regenerated by
`run_all.sh`; per-run JSON includes baseline/peak RSS, timing, input and
output sizes and the boolean `within_256_mib`.

| run | metric | input | seconds | peak growth |
|---|---|---|---:|---:|
| faith_csr_dispersed | faith_pd | csr | 0.67 | 10.0 MiB |
| faith_csr_clustered | faith_pd | csr | 0.76 | 8.9 MiB |
| faith_csrarray | faith_pd | csr_array | 0.76 | 8.9 MiB |
| faith_biom | faith_pd | biom | 0.67 | 13.3 MiB |
| unweighted_csr_dispersed | unweighted_unifrac | csr | 0.69 | 6.5 MiB |
| unweighted_csr_clustered | unweighted_unifrac | csr | 0.66 | 11.5 MiB |
| unweighted_csrarray | unweighted_unifrac | csr_array | 0.88 | 7.9 MiB |
| unweighted_biom / _clustered | unweighted_unifrac | biom | 0.67 | ~12.5 MiB |
| weighted_csr_dispersed | weighted_unifrac | biom | 7.8 | 12.1 MiB |
| weighted_csr_clustered | weighted_unifrac | csr | 4.9 | 10.8 MiB |
| weighted_csrarray | weighted_unifrac | csr_array | 7.8 | 12.2 MiB |
| weighted_biom / _clustered | weighted_unifrac | biom | 4.7-7.9 | 12.1 MiB |
| weightednorm_* (both normalized=True variants) | weighted_unifrac | all | 7.1-11.4 | 9.7-12.5 MiB |

The weighted kernels are O(n_samples^2) Python-level pair walks over the
sparse node columns, which is why they take longer than the linear Faith PD
and vectorized unweighted paths; their memory stays flat because only the
final 256x256 distance matrix and the shared sparse state are held.

## Strategy and trade-off

See the module docstring of `skbio/diversity/_sparse.py` for the full
discussion. In short: a sparse ancestor matrix reduces tip counts to per-node
counts via two sparse products, and pairwise work streams over sparse node
vectors. Memory scales with stored (sample, node) incidences rather than the
table width; per-sample streaming would use less memory still but repeats the
ancestor walk for every pair, while a dense per-node matrix would reintroduce
the full wide-table expansion. No sampling, rare-count dropping, or
approximation is used.
